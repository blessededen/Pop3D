# Pop-3D

계정 로그인·프로젝트 자동 저장: [계정 사용 안내](POP3D-ACCOUNTS.md). **카카오로 시작하기**와 아이디/비밀번호 로그인을 지원한다. GitHub–Vercel 연결 설정은 [배포 안내](POP3D-VERCEL.md)를 참고한다. 실제 외부 인증·배포 검증 여부도 각 문서에 구분해 기록한다.

2026-09-27 사용성 개편: [새 사용법과 검증 기록](UX-GUIDE-20260927.md). 기본 화면에서 공간 설정 → 집기·배치 → 비용 검토 → 기획보고서 순서로 진행한다. 집기 검색과 맞춤 규격 추가도 같은 작업 화면에서 이어진다.

등록된 공간 치수와 업체 카탈로그로 팝업 집기 배치안·수량표·예상 비용을 함께 고치고, 같은 버전의 평면도·3D·기획보고서 PDF를 만드는 웹 도구다. 팀 알칼라인의 Pop-3D 브리프(v2, 2026-09-25) 제안 범위를 구현했다.

> 기본 데이터는 브리프 9장의 **가상 검증 데이터**다. 실제 매장·상품·시장 가격이 아니며, 모든 화면과 PDF에 그렇게 표시된다.

## 실행

```bash
npm install
npm run dev
```

브라우저에서 `http://127.0.0.1:5174`를 연다. 카카오 콜백 주소와 일치하도록 포트를 고정한다. 로컬 실행은 이 PC에서 사용하며, 휴대폰에서 보고서를 열려면 별도 배포와 공유 기능이 필요하다.

- Windows에서는 `run-dev.cmd`를 더블클릭해도 된다. `node`가 PATH에 없으면 `%USERPROFILE%\.local\node`의 포터블 Node를 쓴다.
- 필요 버전: Node 22.18 이상(LTS 24 권장). 배포용 서버가 Node의 TypeScript 직접 실행 기능을 쓴다.

| 명령 | 내용 |
|---|---|
| `npm run dev` | 개발 서버(AI 해석 API 포함) |
| `npm test` | 배치·비용·편집·카카오 로그인 회귀 검사 |
| `npm run build` → `npm start` | 배포용 빌드 후 서버 실행(기본 포트 8787, `run-prod.cmd`) |
| `npm run samples` | `samples/`에 기획보고서 PDF 2개(v1 120만 원, v2 90만 원)와 카탈로그 CSV 생성 |
| `npm run fonts` | PDF용 한글 폰트(Noto Sans KR, OFL) 서브셋 재생성 |

카카오 로그인 및 나와의 채팅으로 보고서 보내기: [POP3D-KAKAO-LOCAL.md](POP3D-KAKAO-LOCAL.md).

## 2분 데모 순서(브리프 10장)

1. **배치·견적** 화면: 왼쪽에서 등록 공간(가상 검증 공간 A)·자료 상태, 일정, 예산 120만 원, 필수 집기(카운터·포토존)를 보여준다.
2. 가운데 평면도·3D에 번호 붙은 집기, 오른쪽에 수량·확인 비용 1,050,000원(예산 대비 150,000원 여유)이 같이 나온다. **버전 확정**으로 v1을 만든다.
3. 예산을 900,000으로 바꾸고 **배치안 제안** → 필수 집기는 유지되고 행거가 4개 → 2개로 줄어 합계 850,000원(50,000원 여유). 조정 내역이 초록 안내로 뜬다.
4. 행거 하나를 빨간 빗금(분전반 앞)으로 끌어 놓는다 → 빨간 표시와 오류, **버전 확정** 비활성. `Ctrl+Z`로 되돌린다.
5. **확정 + 기획보고서 PDF** → v2 PDF의 문서 번호·버전·상품번호·수량·금액을 화면과 대조한다. 운송·설치·철거비 칸에서 철거비 금액을 지우면 ‘미확인’이 되고 ‘최종 총액 미확정’이 표시되며 0원으로 더하지 않는다.

**검증** 화면은 위 시나리오를 브라우저에서 바로 계산해 기대값과 대조한다(9/9 통과).

## 데이터 넣기

- **좌표계**: 평면도 왼쪽 위 모서리가 원점, x는 오른쪽, y는 아래(출입구 쪽), 단위 m. 출입구 위치는 위·아래 벽은 왼쪽 끝부터, 좌·우 벽은 위쪽 끝부터 잰다.
- **카탈로그 CSV**: `samples/카탈로그_가상검증예시.csv`나 화면의 **CSV 템플릿**을 참고한다. 필수 열은 상품번호·상품명·종류·가로·깊이·높이(m). 종류는 `행거/카운터/포토존/테이블/선반/거울/진열대/조명/기타`. 가격 상태를 비우면 기준일·출처가 있을 때만 ‘확인’, 아니면 ‘추정’으로 들어간다.
- **참고 스캔 GLB**: Polycam에서 glTF로 내보낸 파일은 Blender에서 열어 GLB로 다시 내보낸 뒤 불러온다(.glb만 받는다). 크기 비교는 가로·세로 3% 이내면 초록이다. 이 앱이 내보낸 빈 매장 GLB는 벽 두께 0.1m가 바깥쪽에 붙어 외곽이 가로·세로 +0.2m다.
- **저장**: 로그인한 계정별로 서버에 저장된다. 로컬은 SQLite, Vercel은 `DATABASE_URL`로 연결한 Neon을 사용한다. 프로젝트 메뉴(⋯)의 **데이터 백업(JSON)** / **백업 불러오기**로 별도 서버의 계정에 작업을 옮길 수 있다. 참고 스캔 GLB 원본은 백업에 들어가지 않는다.

## AI 설정(선택)

`.env.example`을 `.env`로 복사하고 키를 넣는다. 키는 서버에서만 쓰고 브라우저로 보내지 않는다.

```
ANTHROPIC_API_KEY=...        # 또는 OPENAI_API_KEY=...
AI_PROVIDER=anthropic        # 둘 다 있을 때 선택
```

AI 키가 없어도 배치와 PDF 기능이 동작하며 문장 해석은 규칙 기반 예시 모드로 표시된다. 로그인·계정별 저장에는 서버 API가 필요하므로 `dist`만 정적 호스팅해서는 전체 서비스를 사용할 수 없다. Vercel에서는 제공된 함수 진입점과 영구 DB를 함께 설정한다.

## 구조

```
src/domain/   순수 로직(브라우저·Node 공용): 검사 validate, 비용 cost, 자동 배치 planner,
              버전 version, 견적 패키지 quote, CSV, 문장 해석 interpret, 가상 데이터 seed,
              브리프 시나리오 scenarios, 테스트 domain.test.ts
src/pdf/      기획보고서 PDF(jsPDF + Noto Sans KR 서브셋)
src/three/    공간·집기 3D 생성, 오프스크린 렌더, GLB 내보내기/불러오기
src/components, src/pages   화면
server/       배포용 Node 서버와 AI 해석 API(/api/ai/interpret, /api/health)
```

화면의 수량·비용표와 PDF는 같은 함수(`computeCost` / `buildQuotePackage`)를 쓰고, PDF는 항상 확정 버전 사본으로 만든다.

## 아직 없는 것

- 카카오 알림톡, 결제·발주, 업체 실시간 재고 조회(나와의 채팅 보고서 링크 전송은 지원)
- 여러 사용자가 같은 프로젝트를 동시에 편집하는 협업 기능(현재는 계정별 서버 저장, 저장 충돌 감지)
- 직사각형이 아닌 공간, 사선 벽, 회전된 금지 구역
- 카탈로그의 `3D 모델 URL`은 저장만 하고 화면에는 치수 기반 단순 모델을 쓴다
